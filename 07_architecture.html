REFERENCE STRUCTURE

기능 흐름은 선명하지만 시스템 경계는 약했다

레퍼런스는 필드 → 원정 → 전투 → 보상이라는 플레이 흐름이 분명하다. 반면 여러 객체가 전역 상태를 통해 서로를 직접 호출해 한 사건이 많은 시스템을 동시에 수정한다.

확인

몬스터 사망

한 처리에서 XP·처치 수·드롭·인카운터·통계·영구 포인트 등을 함께 바꾼다.

확인

던전 종료

월드 전환·정복·성 진행·자동 장비·통계·포인트·파티 위치를 직접 변경한다.

확인

파티 목표

목적지 선택뿐 아니라 판매·진입·문 개방과 일부 보상 사건까지 담당한다.

분석 판단서비스 로케이터형 결합

작은 게임을 빠르게 만드는 데는 유리하지만 업데이트 순서가 암묵적이고, 오프라인 결과 일치·부분 테스트·중복 보상 복구가 어려워진다. 신규 프로젝트는 명령과 도메인 사건으로 이 호출 사슬을 끊는다.

ONE SIMULATION

화면과 오프라인이 같은 게임을 실행한다

확인된 레퍼런스요약 공식이 아닌 실제 턴 가속 재생

오프라인에서도 필드 이동, 던전 진입, 방 탐색, 전투, 드롭, 재감염과 시설 생산이 실제 턴 규칙으로 처리된다. 기본 턴은 0.25초이며 한 화면 프레임에서 여러 턴을 묶어 진행한다.

simulateTicks(count, mode)
  mode = FOREGROUND | CATCH_UP
  같은 도메인 규칙
  같은 이름 있는 RNG stream
  같은 명령·사건 처리 순서
  연출만 CATCH_UP에서 요약
정밀 재생

결정이 민감한 구간

현재 전투, 보스, 장비 교체, 철수, 문·층 전환은 실제 사건 경계까지 정확히 재생한다.

시간 점프

결과가 닫힌 구간

안정적인 시설 생산, 타이머, 다음 waypoint 도착은 다음 의미 있는 사건 시각으로 점프한다.

결정성seed만이 아니라 stream과 counter도 저장한다

월드·지형·인카운터·보상 난수를 이름 있는 스트림으로 분리한다. 같은 시작 상태, 정책, seed, tick 순서에서는 화면 실행과 오프라인 실행의 결과가 같아야 한다.

SAVE & LEDGER

공간 전환과 보상 사이에서 끊겨도 안전하다

체크포인트저장해야 할 핵심복구 시 검사
행동 완료 뒤simulationTick, 행동 결과 사건같은 행동 재해결 금지
방 해결 뒤room revision, 획득·미획득 보상보상 원천 ledger 대조
문·계단 전후phase, 양쪽 anchor, transition token리더만 이동한 불가능 상태 방지
던전 정산 전후DungeonCompleted eventId, 노드 상태정복·시설 후보 중복 금지
계승 확정 전후보상 snapshot, ResetPolicy, 새 runId보상 1회·반쪽 초기화 방지
안정 ID모든 보상 원천은 한 번만 닫힌다

상자, 보스, 방, 던전, 지역, 계승마다 안정 ID를 두고 RewardLedger에 완료 여부를 기록한다. 같은 명령을 다시 적용해도 이미 완료된 결과를 반환하는 멱등 처리를 사용한다.

NON-NEGOTIABLES

출시 전에 자동 검증해야 할 불변조건

자원

모든 증감은 원장 항목 하나와 대응하고 잔액은 음수가 되지 않는다.

보상

같은 eventId를 두 번 처리해도 한 번만 정산된다.

원정

FIELD에는 내부 층이 없고, EXPLORING에는 유효한 사이트·층·입출구가 있다.

전투

살아 있는 캐릭터는 한 tick에 최대 하나의 행동 의도만 제출한다.

월드

잠긴 지역은 목표가 될 수 없고 한 사이트에 던전과 시설이 동시에 활성화되지 않는다.

저장

schemaVersion, contentVersion, runSeed, tick, RNG counter가 항상 함께 있다.

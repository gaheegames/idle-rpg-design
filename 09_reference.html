확인된 레퍼런스 신규 제안

METHOD

기획 판단을 세 층으로 기록했다

이미지 출처와 사용 범위David E. Gervais의 타일을 분석 근거로 제한해 사용했다

원본 게임 크레딧은 모든 타일을 David E. Gervais가 제작했다고 밝히고 원 출처를 안내한다. 이후 OpenGameArt 배포 페이지에서 CC BY 3.0 조건을 확인했다. 분석용 예시는 공개 페이지에 제한해 싣고, 승인된 전체 아카이브와 해시·크레딧 정책은 비공개 게임 저장소에 보존한다. 자세한 결론은 사용자 연구와 자산 정책에 정리했다.

확인

코드 사실

분기, 상태 변화, 상수, 데이터 개수, 호출 순서를 역컴파일된 게임플레이 코드에서 직접 확인했다. 파일과 관련 줄 범위를 함께 기록한다.

해석

시스템 판단

여러 코드 경로를 연결해 콘텐츠 순환, 병목, 장기 플레이 영향을 해석했다. 코드 사실과 구분해 문장으로 설명한다.

신규 제안

클린룸 설계

레퍼런스의 코드·표현·수치를 복제하지 않고 행동 원리와 문제를 바탕으로 새 상태, 공식, 콘텐츠 범위를 설계했다.

범위게임 기획과 게임 구조만 분석

전투, 탐색, 던전 생성, 필드 이동, 보상, 성장, 시설, 지역 정복, 오프라인, 승리·계승만 근거 대상으로 삼았다. 지원 단말, 패키지 이름, SDK, 권한, 배포와 같은 게임 외 항목은 이 페이지와 전체 기획에서 제외했다.

CONFIDENCE LEVELS

“보였다”와 “그렇게 느껴질 것이다”의 신뢰도는 다르다

등급판정 기준이 문서의 예추가 검증
높음상수·분기·상태 변경·호출 경로가 직접 존재필드 목표 순서, 문 개방 조건, 재감염 tick, 프레스티지 보존 범위단위 테스트로 재현 가능
중간여러 코드 경로의 결합 효과를 논리적으로 추론근거리 던전 과반복, 계속하기 우세 가능성, 복리 폭주 위험장시간 시뮬레이션·플레이 로그 필요
미확정정적 코드만으로 실제 빈도·체감·운영 결과를 단정할 수 없음정체가 실플레이에서 얼마나 자주 발생하는지, 특정 빌드의 실제 우세율실행 재현·텔레메트리 필요
제안새 프로젝트를 위한 독립 설계18상태 Director, 7단계 복구, 5자원 체계, 8상태 필드 노드프로토타입·밸런스 테스트 대상
높은 신뢰

자동 탐색 호출 흐름

PartyGoal, PartyCharacterBrain, ExploreDungeonBehavior, DoorPathFinder를 연결해 방 정지·문 선택·경로·집결·계단 전환을 추적했다.

높은 신뢰

성 자동화 단절

CastleAutomation은 존재하지만 AutomationManager의 생성·turn 갱신 경로에 등록되지 않은 것을 직접 비교했다.

중간 신뢰

장기 반복 피로

고정 seed, 최근접 목표, 재감염 공급량은 직접 확인했지만 플레이 체감의 크기는 실제 장시간 로그로 보정해야 한다.

설계 가설

새 시간·수치 범위

방 20~60초, 던전 8~20분, 지역 구성 3~5개 같은 값은 레퍼런스 사실이 아니라 초기 플레이테스트용 목표다.

EVIDENCE → DECISION

확인 사실이 어떤 신규 설계로 이어졌는가

확인된 사실분석한 위험·가치신규 설계 결정상세 페이지
공용 목표와 캐릭터 행동 점수 분리탐험과 전술 책임 분리는 유효ExpeditionDirector + AgentBrain 계약자동 탐색, 구조
문 후보가 좌표 거리와 첫 발견 경로에 의존화면상 가까우나 실제로 먼 문 선택 가능실제 그래프 비용 기반 frontier 점수자동 탐색
집결이 같은 방·복도 객체 여부 중심문과의 실제 거리·후속 통과 보장이 약함formation anchor + 문·계단 원자 전환자동 탐색
무제한 생성 재시도 경로희귀 seed에서 영구 정지 가능최대 시도 + 검증 + 안전 템플릿던전
정복과 재감염 상태 분리진척 보존과 반복 파밍을 함께 만족8상태 필드 노드 + 가역 시설 전환필드
처치 수가 강화와 적 단계 해금에 함께 사용경제 투자가 콘텐츠 해금을 지연런 자원과 비소비 진행 상태 분리성장
판매금·농장 수익이 수동 버퍼에 머묾방치 진행이 접속 확인에 의존즉시 원장 정산, 보상함은 기록용성장
오프라인이 실제 턴 규칙을 재생빌드 충실도는 높지만 장시간 비용 증가동일 커널 + 사건 경계 시간 점프구조
프레스티지와 계속하기 두 갈래새 조합과 빌드 한계 시험을 모두 수용계승·심층 계속에 서로 다른 독점 보상성장

LIMITS & NEXT VALIDATION

정적 분석으로 답할 수 없는 것은 테스트 항목으로 남긴다

빈도

희귀 정체의 실제 발생률

명시적 watchdog이 없다는 사실은 확인했지만 어떤 seed·파티에서 얼마나 자주 멈추는지는 대량 실행으로 측정해야 한다.

체감

콘텐츠 피로와 선택 만족

고정 지도와 근거리 반복이 피로 요인이라는 판단은 타당하지만, 임계 횟수와 개인차는 플레이테스트가 필요하다.

밸런스

신규 제안 수치

시간 범위, 점수 가중치, 시설 생산량, 5자원 공급·소비는 프로토타입 경제 로그로 조정해야 한다.

최적화

오프라인 시간 점프 오차

초기에는 완전 일치를 요구하고, 사건 점프를 도입한 뒤 평균 1%·95백분위 3% 이내 목표를 검증한다.

검증 전략모르는 것을 기능 가정으로 숨기지 않는다

미확정 항목은 seed, 명령 로그, 정책, 결과 해시를 남기는 자동 실험으로 전환한다. 밸런스와 체감은 버전별 가설·지표·판정 기준을 기록한다.

CLEAN-ROOM DESIGN

원리를 배우고 구현은 새 계약으로 만든다

  1. 행동 의미만 문서화어떤 상태에서 무엇을 선택하고 어떤 결과가 생기는지 독립 언어로 적는다.
  2. 문제와 목표를 다시 정의“코드를 옮긴다”가 아니라 “무인 탐색이 유한 시간 안에 끝난다”처럼 제품 조건으로 바꾼다.
  3. 새 데이터·상태·수식 사용18상태 Director, utility 점수, 원장, 8상태 필드 노드처럼 신규 계약으로 구현한다.
  4. 레퍼런스 수치를 기본값으로 오인하지 않음확인 값은 비교 기준일 뿐 새 게임 밸런스는 자체 테스트로 결정한다.
  5. 테스트가 최종 사양종료성, 결정성, 중복 방지, 설명 가능성을 자동 검증해 구현의 정답을 고정한다.

레퍼런스의 본질은 숫자나 코드가 아니라, 전투가 성장을 만들고 성장이 던전·지역·다음 런을 다시 여는 연결성에 있다.

질문에 대한 직접 답 자동 탐색의 정리와 알고리즘 추출은 완료되었다. 아래 내용은 분석 메모가 아니라 신규 프로젝트의 구현 계약이다.

레퍼런스에서 확인된 실제 행동

방 평가→ 전투 / 드롭 / 장애 대기→ 닫힌 문 선택→ 문으로 이동→ 집결·회복→ 문 개방→ 새 방 평가

현재 방에 살아 있는 적이 있거나 회수할 드롭이 있으면 파티 이동을 멈춘다. 같은 방의 영웅이 행동불능이면 진행을 보류한다. 방·복도에서 닫힌 문을 찾고, 공개된 열린 문·복도만 중간 경로로 사용하며, 목표 닫힌 문은 종점으로 허용한다. 더 이상 닫힌 문이 없으면 출구 계단으로 향한다.

경로와 집결의 실제 형태

확인

상위 경로

방↔문↔복도를 재귀 DFS로 따라 첫 번째 유효 경로를 사용한다. 문 후보는 그래프 최단거리보다 좌표상 가까움의 영향을 많이 받는다.

확인

지역 이동

방 안에서는 목표 좌표로 직접 이동하고, 복도에서는 생성 시 저장한 waypoint를 따른다.

위험

집결 판정

문과의 실제 거리가 아니라 같은 방 또는 같은 복도 객체인지 확인한다. 선두 1인 도착만으로 층 전환도 가능하다.

그대로 가져오면 안 되는 지점

신규 시스템의 책임 경계

공용 탐험 목표와 캐릭터별 전술을 분리한다는 원리는 유지한다. 단, 누구도 다른 계층의 결정을 몰래 바꾸지 못하게 입력과 출력을 고정한다.

Director는 변경 가능한 월드 객체를 직접 읽지 않고 한 tick의 일관된 스냅샷만 받는다. 경로·목표·문·오브젝트는 객체 포인터가 아니라 안정 ID로 저장하고, 로드 시 현재 floorRevision에 다시 연결한다.

공용 Director 상태 기계

명세에는 18개의 진행·종료 상태와 별도의 FAILED 상태가 있다. 구현은 기능별 묶음으로 읽는 편이 쉽다.

초기화 BOOTSTRAP → ASSESS_ROOM
방 처리 FIGHT · WAIT_FOR_DISABLED · RECOVER_RESOURCES · COLLECT · INTERACT
목표·경로 SELECT_OBJECTIVE → PLAN_ROUTE → FOLLOW_ROUTE
문 전환 GATHER_AT_DOOR → OPEN_DOOR → CROSS_DOOR → ASSESS_ROOM
층 전환 APPROACH_EXIT → USE_EXIT → FLOOR_COMPLETE
종료·복구 RECOVER_STUCK · EXPEDITION_COMPLETE · FAILED

모든 상태보다 먼저 적용하는 인터럽트

  1. 종료 상태 확인 층·원정이 끝났거나 이미 실패했으면 종료 상태로 고정한다.
  2. 전멸 확인 필수 구성원이 전멸했으면 명시적으로 실패한다.
  3. 새 위협 현재 파티 노드에 위협이 생기면 이동·수집을 취소하고 전투한다.
  4. 행동불능 전투가 없고 필수 구성원이 행동불능이면 대기·지원한다.
  5. 정체 요청 watchdog이 발동했으면 복구 상태로 전환한다.
  6. 현재 상태 위 조건이 없을 때만 원래 상태 로직을 계속한다.

방 처리 우선순위

if liveThreatCount > 0         → FIGHT
else if required member disabled → WAIT_FOR_DISABLED
else if resources are insufficient → RECOVER_RESOURCES
else if policy allows remaining loot → COLLECT
else if required/allowed interaction → INTERACT
else                               → SELECT_OBJECTIVE

전투 종료 뒤에는 바로 이전 경로를 재개하지 않고 반드시 방을 다시 평가한다. 그래야 방금 생성된 드롭, 행동불능, 새 상호작용을 놓치지 않는다.

Frontier 선택 알고리즘

frontier는 현재 알려진 그래프에서 가까운 쪽까지 도달할 수 있는 닫힌 문이다. 봉인 조건, blacklist, 미해결 여부를 통과한 후보만 점수화한다.

frontierScore = wN × novelty + wO × objectiveAffinity + wR × expectedReward − wP × normalizedPathCost − wD × predictedDanger − wB × backtrackRatio − wF × failureRatio − wQ × resourcePressure × predictedDanger
신호기호제안 기본 가중치의미
새 영역 가치N+40미공개 영역 선호
현재 목표 적합도O+50퀘스트·키·보스·출구 관련성
기대 보상R+20정찰 정보로 추정한 가치
실제 경로 비용P−25알려진 그래프 최단 비용
예상 위험D−35전투·함정·환경 위험
최근 역주행B−15최근 방문 edge 반복
실패 이력F−60세 번 실패 시 일시 blacklist 권장
자원 압박Q−30×D약한 파티가 위험 방을 피하게 함

신규 제안 모든 항은 0..1로 정규화한다. 동점은 실제 경로 비용 → 실패 횟수 → 안정 ID 순으로 풀며 프레임별 난수를 쓰지 않는다.

새 위협, 문 상태 변경, 새 방 공개, 필수 구성원 node 불일치, 국소 경로 2회 실패, 목표 소멸, floor revision 변경 시 경로를 폐기한다. 문 통과 뒤에는 반대편 exit anchor까지 이동시켜 문 위 정체를 막는다.

문 앞 집결과 원자 전환

슬롯 배정→ 필수 인원 집결→ 2 tick 안정→ 상태·자원 확인→ 문 열기 1회→ 전원 반대편 통과

각 문은 가까운 쪽 집결 중심·개별 슬롯·상호작용점·반대편 이탈 중심·슬롯을 가진다. 필수 구성원이 모두 가까운 쪽 node에 있고 배정 슬롯 오차가 허용치 이하이며, 행동불능·전투·상호작용 중이 아니어야 한다.

판정신규 초기값운영 원칙
집결 허용 반경캐릭터 충돌 반경 × 1.5문마다 실제 슬롯까지의 거리로 판정

신규 제안 임계값은 레퍼런스의 40%/30%를 복제한 값이 아니며 전투 템포 테스트로 데이터 조정한다.

계단도 문과 같은 전환 자원이다

목표 조건 완료, 지역 위협 없음, 필수 인원 생존·집결, 필수 상호작용 완료를 모두 확인한 뒤 USE_EXIT 하나로 층 결과 저장→명령 취소→층 증가→다음 seed 로드→입구 슬롯 배치→revision 증가를 처리한다.

ProgressWatchdog와 7단계 복구

정체는 “캐릭터 좌표가 안 움직임”이 아니다. 상태마다 의미 있는 진행 신호가 다르며, 그 신호가 멈췄을 때만 복구 단계를 올린다.

상태군진행으로 인정하는 신호
이동다음 waypoint 거리 감소 · graph node 변경 · segment 완료
집결준비 인원 증가 · 슬롯 오차 합 감소
전투위협 수·적 HP 감소 · 유효 행동 발생
회복최저 HP·자원 증가 · 행동불능 인원 감소
수집·상호작용대상 감소 · 예약 변경 · 진행도 증가
문·계단명령 승인 · 상태 변경 · floor revision 증가
  1. 2초 · Local path 재계산 정체된 캐릭터의 국소 경로만 다시 구한다.
  2. 5초 · 진형 재배정 formation slot을 바꾸고 동적 회피 캐시를 초기화한다.
  3. 8초 · Graph route 재계산 실패 edge 비용을 올리고 상위 경로를 다시 구한다.
  4. 12초 · 문 blacklist 현재 문을 30초 제외하고 다른 frontier를 고른다.
  5. 18초 · 안전 지점 재집결 유효 경로로 마지막 안전 방 anchor에 모은다.
  6. 25초 · 안전 복원 정책 허용 시 snapshot rollback 또는 같은 seed로 층을 다시 연다.
  7. 복구 주기 2회 실패 · 종료 원정을 명시적으로 실패시키고 seed·상태·edge를 진단 로그에 남긴다.
유한 종료가 품질 기준이다 방치형 게임에서는 “어떻게든 계속 시도”보다 “제한 시간 안에 성공하거나 이유가 있는 실패로 끝남”이 중요하다. 무한 재계획은 복구가 아니라 또 다른 정체다.

세이브·오프라인 결정성

  • 새 방 해결, 문 열기 직전, 출구 사용 직전에 경량 안전 snapshot을 만든다.
  • floor seed/revision, 공개 상태, 파티 anchor, Director 목표·blacklist, RNG cursor를 저장한다.
  • 완료된 전리품·상호작용·보상 ID는 단조 증가 ledger에 별도 기록한다.
  • 오프라인도 같은 상태 기계를 실행하되 waypoint·행동 완료 같은 이벤트 경계까지 시간을 점프한다.
  • 같은 seed·정책·시작 상태·tick 순서는 같은 목표와 명령 로그를 만든다.

반드시 지킬 불변조건

공간

닫힌 문을 통과하지 않고, 미공개 방을 중간 경로로 쓰지 않으며, revision이 바뀌면 이전 경로를 폐기한다.

파티

집결 token 없이 문을 열지 않고, 필수 인원 집결 없이 층을 바꾸지 않으며, 전투 중 탐색 수집을 병행하지 않는다.

결과

같은 보상 ID는 한 번만 지급하고 모든 비종료 상태는 유한 시간 안에 진행 또는 복구로 전이한다.

완료 검증 목표

  • 유효한 10,000개 던전 seed가 모두 완료 또는 명시적 실패에 도달한다.
  • 필수 구성원이 문·계단 뒤에 유실되는 경우가 0이다.
  • 동일 입력·seed·tick의 목표·명령 로그 해시가 동일하다.

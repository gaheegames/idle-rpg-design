04 · PROCEDURAL DUNGEON

방을 무작위로 놓는 것이 아니라
선택의 리듬을 생성한다

레퍼런스의 결정적 기하와 지연 생성은 유지할 가치가 있다. 신규 생성기는 연결성에 그치지 않고 주요 경로, 선택 분기, 위험·보상 예산, 출구 거리와 해결 가능성을 검증해 한 층의 플레이 경험까지 보장한다.

레퍼런스 생성 구조의 핵심

필드 던전 메타데이터는 이동 중 생기는 것이 아니라 월드 구성 시 선계산된다. 던전 안에서는 필드 좌표와 층 인덱스로 구조를 재현하고, 아직 열지 않은 방의 인카운터는 문을 열 때 실체화한다.

트리 맵이 만드는 실제 플레이

입구→ 주요 갈림길↗ 막다른 보상↩ 주요 갈림길→ 출구

모든 방이 연결되고 구조를 읽기 쉽다는 장점이 있지만, 두 갈래가 다시 만나는 지름길이 없다. 자동 탐색은 막다른 분기에서 반드시 같은 복도를 되돌아와야 하며, “어느 길이 안전하거나 효율적인가”보다 “어느 막다른 길을 먼저 소비할까”에 가까운 선택만 남는다.

확인된 품질 위험

거리

임의 출구

입구와 출구 사이 최소 거리를 검사하지 않아 한두 방 만에 층이 끝날 수 있다.

실패

무제한 재시도

생성 전체의 시도 횟수·시간 예산·검증된 폴백이 없다.

재현

난수 경계 혼합

기하는 재현되지만 몬스터·상자·장식은 다른 난수원에 의존한다.

검증

품질 검사 부족

출구 거리, spawn 안전 반경, 문 좌표 중복, 전체 flood-fill 품질을 검사하지 않는다.

배치

북서 편향

배치된 방을 북서로 밀어 넓은 캔버스 한쪽에 군집이 생긴다.

저장

배열 순서 의존

방·복도 델타가 생성 코드 버전의 배열 순서에 의존한다.

신규 던전 생성의 다섯 목표

01

읽을 수 있음

주요 경로와 선택 분기의 의미가 화면과 탐색 로그에서 드러난다.

02

결정성

같은 seed와 명령 로그는 같은 공간·인카운터·보상을 만든다.

03

복구 가능

생성 실패는 정해진 횟수 뒤 검증된 템플릿으로 끝난다.

04

데이터 조절

방 수, 분기, 거리, 전투·보상 밀도를 profile로 조절한다.

05

동일 규칙

화면 실행과 오프라인 계산이 같은 층 결과를 사용한다.

난수 스트림을 목적별로 분리한다

이름 하나를 추가했더니 뒤쪽 던전 위치가 바뀌거나, 장식 변경이 보스 조합을 바꾸는 일이 없어야 한다. 각 스트림은 root seed, 안정 domain tag, entity ID, floor에서 파생한다.

토폴로지 먼저, 기하는 나중에

방 위치부터 뽑고 우연히 생긴 연결을 쓰지 않는다. 먼저 이 층이 제공해야 할 선택을 그래프로 만든 다음 화면 공간에 배치한다.

  1. 프로필 결정 지역 테마, 위험 티어, 던전 목적, 층 수와 난도 예산을 정한다.
  2. 토폴로지 생성 주요 경로 길이, 선택 분기, 막다른 보상실, 소수의 순환 edge를 만든다.
  3. 방 역할 배정 전투·엘리트·보물·사건·회복·출구 quota를 지킨다.
  4. 기하 배치 그래프 노드를 방 크기·좌표로 변환하고 충돌·여유 공간을 검사한다.
  5. 복도 라우팅 정해진 path budget 안에서 모든 edge를 실제 복도로 잇는다.
  6. 입구·출구 선택 그래프 거리 기준을 만족하는 먼 출구를 고르고 계단 안전 반경을 확보한다.
  7. 콘텐츠 예산 배분 전투·위험·보상·회복 예산을 방 역할과 경로 위치에 맞춰 나눈다.
  8. 해결 가능성 검증 키·봉인 의존성과 모든 필수 방 도달 가능성을 확인한다.
  9. 유한 재시도 최대 횟수까지 실패하면 즉시 검증된 폴백 템플릿을 사용한다.
BuildFloor(profile, seedSet):
  for attempt in 0 .. profile.maxAttempts - 1:
    graph     = BuildRoomGraph(profile, topologyStream(attempt))
    rooms     = PlaceGeometry(graph, geometryStream(attempt))
    corridors = RouteEdges(rooms, graph, profile.pathBudget)

    if placement or routing failed: continue

    entrance = ChooseEntrance(graph)
    exit     = ChooseFarExit(graph, entrance, profile.exitPercentile)
    report   = ValidateFloor(graph, rooms, corridors, entrance, exit)

    if report.ok: return Floor(...)

  return BuildGuaranteedFallbackFloor(profile)

방 역할이 콘텐츠 조합의 문법이다

BASELINE

일반 전투실

기본 성장 재료와 현재 빌드의 지속 전투 능력을 검사한다.

RISK

엘리트실

높은 위험 대신 유물 조각·빌드 핵심 보상을 준다.

ECONOMY

보물실

전리품 정책과 인벤토리 판단을 일으킨다.

CHOICE

사건실

조건부 선택으로 런 규칙과 위험·보상 구성을 바꾼다.

RHYTHM

회복실

다음 위험을 감당하게 하는 리듬 장치이자 안전 snapshot 지점이다.

GATE

봉인·퍼즐실

키, 능력, 직업 조합을 검사하되 필수 경로를 막으면 해결 순서를 검증한다.

한 층의 위험과 보상을 예산으로 묶는다

floorBudget = baseBudget × depthFactor × regionDanger × activeModifier

총예산을 전투, 환경 위험, 보상, 회복에 배분한다. 전투 예산이 올라가면 보상 예산도 따라 올라가야 하며, 선택 분기의 기대 보상은 추가 이동·전투 비용보다 조금 높아야 한다.

  • 회복실은 공짜 보상이 아니라 다음 고위험 구간을 가능하게 하는 템포 장치다.
  • 보스 직전에는 무작위로 치명적인 encounter tag 조합을 제한한다.
  • 목표 직행·완전 탐색 어느 한쪽만 항상 정답이 되지 않게 자원 압박과 선택 보상을 함께 둔다.
  • 동일 지형을 재사용해도 population seed와 modifier로 다른 전투 구성을 만들 수 있다.

필수 생성 검증과 폴백

연결성

입구에서 모든 필수 방과 출구에 도달 가능하며 키·봉인 의존성이 위상 순서를 만족한다.

거리

입구→출구가 그래프 지름의 60% 이상 또는 프로필의 최소 3–4간선을 충족한다.

공간 안전

문·계단 좌표가 겹치지 않고 계단 2타일 반경에 문·상자·몬스터가 생성되지 않는다.

구조 계약

각 문이 정확히 방 하나와 복도 하나에 연결되고 복도 폭·벽 여유가 기준을 만족한다.

밀도

방 면적 대비 최대 동시 적 수, 막다른 길 비율, 총 이동 거리와 바닥 셀 수가 목표 구간에 있다.

시간 예산

시도 횟수 또는 생성 시간 예산을 넘기면 더 시도하지 않고 즉시 폴백한다.

폴백은 예외가 아니라 제품 기능 폴백 층도 같은 방 역할 quota, 안정 ID, seed 파생, 보상 예산을 가진 검증된 템플릿이어야 한다. “빈 직선 맵”으로 게임 규칙을 우회하지 않는다.

생성된 층의 런타임 수명 주기

SEED 확정→ 기하 생성·검증→ 입구 공개→ 문 개방 시 콘텐츠 생성→ 방 해결·델타 기록→ 층 완료

세이브에는 전체 타일 배열 대신 generationVersion, seed set, 안정적인 Room/Door/Object ID, 공개·개방·완료 델타를 기록한다. 생성 코드가 바뀌면 버전별 생성기 또는 명시적 마이그레이션으로 이전 세이브를 보호한다.

던전 시스템 완료 기준

  • 10,000개 seed의 모든 필수 방·출구가 도달 가능하거나 제한된 생성 단계에서 폴백된다.
  • 동일 seed set·generationVersion은 동일한 그래프·방 역할·콘텐츠 ID를 만든다.
  • 입구→출구 거리, 분기, 막다른 길, 순환로, 전투·보상 예산 분포가 profile 범위 안에 든다.
  • 저장·로드 뒤 공개 상태, 문, 전리품, 상호작용과 보상이 정확히 복원된다.
  • 생성 실패가 무한 로딩으로 이어지는 경우가 0이다.
도식 원본 모아 보기 이 페이지의 던전 층 재구성도, 생성 다섯 단계, 문 통과 상태도와 전투 화면 초안은 시각 자료실에서 원본 크기와 사용 상태를 함께 확인할 수 있다.

토폴로지 먼저, 기하는 나중에구현생성기를 이 장의 단계 순서대로 재작성했다. 단일 시도 실패율이 75%에서 33.6%로 내려갔다(2,000던전 표본)
검증된 폴백 템플릿구현재설계했다. 기존 일자 구조 템플릿은 자기 자신의 검증을 통과하지 못했다 — 폴백이 “빈 직선 맵”이면 안 된다는 이 장의 요구를 지키지 못하고 있었다
필수 생성 검증 6항목부분6항목을 모두 판정하지만 3항목이 부분 판정이다. 공간 안전은 계단 반경 검사가 정본 기하에서 구조적으로 발동하지 않고 상자·몬스터를 보지 않는다. 구조 계약은 복도 폭과 벽 여유를 보지 않는다. 밀도는 총 이동 거리와 바닥 셀 수를 보지 않는다
규모 밴드 판정 범위부분방 7개 이상인 층에서만 밴드를 판정하며, 면제 대상이 대규모 생성 표본의 41.4%다. 방 4개는 구조적으로 밴드를 만족할 수 없지만 5·6개는 가능하다. 면제는 “일반 던전 프로필을 소형 던전에 적용하지 않는다”는 판단이며, 판정을 피하려는 조치가 아님을 밝혀 둔다
생성 실패 시 제한 횟수 내 수선부분수선이 고아 방만 고친다. 실제 실패 사유는 밴드와 거리인데 그쪽은 손대지 못해 대규모 표본에서 수선 성공이 한 건도 없었다. 실질적인 복구 수단은 재시도뿐이다
봉인·퍼즐실의 “필수 경로 차단 시 해결 순서 검증”미이행봉인·퍼즐실을 막다른 방에만 배치해 검증 상황 자체를 만들지 않았다. 정본 준수가 아니라 정본 회피다. 실제 플레이에서 발동이 거의 없어 사실상 없는 콘텐츠에 가깝다
선택 분기 층당 1~3개미이행검사하지 않는다
밀도 — 방 면적 대비 최대 동시 적 수미이행값은 정했으나 전투 생성에 연결하지 않았다. 선언만 있고 쓰이지 않는 상태다

생성 통계는 대규모 생성 표본에서 측정했다. 단일 시도 실패율은 2,000던전 표본 기준이다. 표본을 밝히지 않은 수치는 인용하지 않는다.

이 장 안에서 정본끼리 어긋나는 지점 방 역할이 방 역할에서는 봉인·퍼즐을 포함하고 출구를 빼는 반면, 생성 파이프라인에서는 출구를 넣고 봉인을 뺀다. 구현은 전자를 따랐고 출구는 보스 방이 겸한다 — 입구·출구·보스는 모든 층에 반드시 있는 구조 요소라 역할 추첨 밖에서 정해지기 때문이다. 방 수도 토폴로지 프로필의 7~11과 규모 비교도의 소형 4~7 · 보통 8~16이 서로 다르다. 앞은 “일반 던전” 한 종류의 값이고 뒤는 던전 규모별 값이라, 사이트마다 규모가 다른 현재 구조에서는 후자를 따랐다. 이 두 건은 구현이 해결할 문제가 아니라 기획서가 정리해야 할 문제다.

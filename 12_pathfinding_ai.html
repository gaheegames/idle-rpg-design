REUSABLE CORE · AI v0.1.0

게임을 실행하지 않아도 같은 입력으로 같은 결정을 검증한다

Pathfinding AI는 특정 엔진의 씬, 캐릭터 객체, 애니메이션과 UI를 직접 참조하지 않는다. 직렬화 가능한 스냅샷과 설정을 입력받아 목표 결정, 경로, 이동 명령, 생성 결과와 설명 로그를 반환한다.

게임은 세계의 현재 사실을 제공하고 명령을 실행한다. AI 코어는 그 사실을 바꾸지 않은 채 “어디로, 왜, 어떤 순서로 움직일지”만 결정한다.

Pathfinding AI

순수 알고리즘과 검증

목표 점수화, 계층형 A*, 파티 대형 계획, 전환 프로토콜, 던전 생성·수선·폴백, 교착 감지, 설명 기록과 헤드리스 테스트를 소유한다.

⇄
Game Build

월드 상태와 실제 실행

전투, 장비, 애니메이션, 물리, 입력, 렌더링, 저장 슬롯과 시간 진행을 소유한다. 어댑터를 통해 스냅샷과 명령 결과만 교환한다.

INPUT

읽기 전용 스냅샷

노드·간선·비용·잠금·위험·파티 발자국·정책·seed·설정 버전을 값 객체로 받는다. 코어는 게임 객체의 주소나 생명주기를 알지 못한다.

OUTPUT

의도와 증거

선택한 목표, 계층 경로, 멤버별 waypoint, 전환 명령, 생성 결과, 실패 코드와 선택 이유를 반환한다. 직접 위치나 자원을 변경하지 않는다.

REUSE

게임 밖 재생

저장된 스냅샷과 명령 결과를 헤드리스 실행기에 넣어 CI, 밸런스 실험, 맵 제작 도구와 다른 프로젝트에서 같은 코어를 재사용한다.

HIERARCHICAL PATH PLANNING

월드에서 방향을 잡고, 지역에서 통로를 고르고, 로컬에서 발을 옮긴다

모든 이동을 하나의 거대한 타일 A*로 계산하지 않는다. 목적과 변화 속도가 다른 세 그래프를 분리하고, 막힘이 생긴 층만 다시 계산한다.

L0 · WORLD어느 권역·정착지·던전으로 갈 것인가월드 노드, 교역로, 위협, 잠금 조건과 장기 정책을 사용한다.
L1 · REGION어느 사이트·입구·방 연결을 통과할 것인가지역 그래프, 문·계단, 방문 상태, 위험 예산과 발견 정보를 사용한다.
L2 · LOCAL현재 공간에서 어떤 waypoint로 움직일 것인가nav grid·polygon, 동적 장애물, 발자국 크기와 상호작용 anchor를 사용한다.
FORMATION파티 각 멤버가 어느 슬롯을 점유할 것인가리더 한 명의 선을 복사하지 않고 멤버별 충돌 없는 슬롯 경로를 만든다.

계획에는 worldRoute, regionRoute, activeLocalSegment, 비용, 사용한 snapshotVersion과 invalidate 조건을 함께 저장한다. 게임은 전체 경로를 임의로 해석하지 않고 현재 실행 가능한 segment만 명령으로 받는다.

SNAPSHOT BOUNDARY

결정은 불변 스냅샷 하나에서 끝낸다

평가 도중 월드가 바뀌어 후보마다 다른 상태를 읽지 않는다. 계산이 끝난 뒤 snapshotVersion이 달라졌으면 결과를 폐기하고 새 스냅샷으로 다시 시작한다.

STABLE TIE-BREAK

동점도 같은 순서로 결정한다

후보 점수가 같을 때 컬렉션 순서나 프레임 타이밍에 기대지 않는다. 안정 ID 또는 명시적 RNG stream을 사용하고 그 선택을 로그에 남긴다.

EVENT-DRIVEN

재평가 사건을 제한한다

목표 완료·무효화, 경로 이탈, 문 상태 변경, 위험 임계 초과, 정책 변경, 진행 watchdog 만료에서만 상위 결정을 갱신한다.

BOUNDED WORK

모든 재시도에는 상한이 있다

탐색 노드 수, 로컬 재경로, 대체 frontier, 생성 수선과 재생성 횟수를 예산으로 제한한다. 예산 소진은 침묵하는 멈춤이 아니라 실패 코드다.

교착 복구 사다리

  1. 진행도 재확인거리·노드·상태 변화가 watchdog 범위 안에서 있었는지 판정한다.
  2. 현재 segment 재경로동적 장애물과 점유 정보를 새로 받아 L2만 다시 계산한다.
  3. 파티 재집결흩어진 멤버를 마지막 안전 anchor로 모으고 formation 슬롯을 다시 배정한다.
  4. 직전 anchor 후퇴문·계단·방 중심 같은 안정 지점으로 원자적으로 되돌아간다.
  5. 지역 대체 경로막힌 edge를 임시 blacklist하고 L1의 다른 문·통로를 찾는다.
  6. 대체 목표 선택현재 후보를 사유와 만료 조건이 있는 blacklist에 넣고 다음 frontier를 평가한다.
  7. 안전 폴백 또는 명시적 실패귀환·대기·검증 템플릿 중 계약된 결과로 끝내고 failureCode와 마지막 유효 anchor를 반환한다.

DETERMINISTIC DUNGEON GENERATION

seed를 바로 타일로 바꾸지 않고, 플레이 가능한 그래프를 먼저 만든다

PARTY FORMATION & ATOMIC TRANSITION

문과 계단은 좌표 하나가 아니라 파티 전체의 전환 프로토콜이다

리더가 문을 지나면 나머지가 순간이동하는 방식은 저장·복구와 충돌한다. 문, 계단, 포털, 지역 출입구를 같은 Transition 계약으로 처리하고 필수 멤버의 집결과 완료를 논리적으로 원자화한다.

SELECT→ APPROACH→ GATHER→ STABILIZE→ COMMIT→ CROSS→ RELEASE
GATHER

멤버별 슬롯 집결

entry anchor 주변에 파티 발자국과 우선순위를 반영한 개별 슬롯을 만든다. 필수 멤버가 허용 오차 안에서 일정 시간 안정되면 집결 완료다.

POLICY

행동불능 멤버 규칙

부상·기절·운반 대상의 포함 여부는 게임 어댑터가 requiredMemberMask와 traversal capability로 전달한다. 코어가 임의로 동료를 버리지 않는다.

COMMIT

원자적 커밋

transitionId, entry·exit anchor, memberMask, phase와 사전조건 해시를 기록한다. 중간 저장은 토큰을 재개하거나 커밋 이전 상태로 안전하게 되돌린다.

DOOR

문 개방

잠금·상호작용·전투 상태를 확인한 뒤 한 번만 open 명령을 낸다. 같은 commandId 재전송은 중복 효과가 없는 멱등 실행이어야 한다.

STAIR

계단·맵 전환

목적 맵 준비 완료를 어댑터에서 확인하고 커밋한다. 로딩 실패 시 entry anchor로 복귀하고 failureCode를 남긴다.

EXIT

반대편 이탈 확인

모든 필수 멤버가 exit 슬롯을 점유하고 포털 충돌 영역을 벗어난 뒤에만 route edge를 완료 처리한다.

완료 불변조건파티는 전환 전·후 어느 쪽에서도 설명 가능한 완전한 상태다

리더만 다음 층에 있고 동료는 이전 층에 남은 상태, 닫힌 문 안에 캐릭터가 끼인 상태, 로드 후 문 보상이 두 번 실행되는 상태를 허용하지 않는다.

DETERMINISM · EXPLAINABILITY · CORPUS

재현할 수 없는 길찾기 오류는 수정할 수 없는 오류다

모든 결정은 seed, 알고리즘·설정 버전, 정규화된 스냅샷과 이전 명령 결과로 재생할 수 있어야 한다. 설명 로그는 디버그 문자열이 아니라 안정된 데이터 계약으로 남긴다.

결정성 해시 100%

같은 seed·snapshot·config·command result가 목표, 경로, 생성 그래프와 최종 해시까지 일치한다.

Golden seed 256+

대표 topology와 과거 버그 seed를 고정 코퍼스로 보존하고 결과 변경을 명시적으로 검토한다.

Release fuzz 10,000+

무작위 spec·seed가 성공, 검증 수선 또는 명시적 폴백 안에서 유한 종료하는지 확인한다.

전환 재생 100+

집결·커밋·교차 각 지점의 저장·로드·중복 명령을 재생해 파티 분리와 이중 처리를 찾는다.

교착 soak 8h

동적 장애물과 전투 중단을 포함한 장시간 실행에서 무기한 정지 없이 복구 또는 실패 코드로 끝난다.

설명 누락 0

후보 탈락, 목표 선택, 재계획, 수선, 폴백에는 machine-readable reasonCode가 반드시 존재한다.

GAME ADAPTER CONTRACT

게임마다 달라지는 것은 어댑터에, 재사용할 판단은 코어에 둔다

어댑터는 게임 상태를 코어의 안정된 schema로 번역하고, 코어의 의도를 게임 명령으로 실행한다. 양쪽은 객체를 공유하지 않고 버전이 붙은 요청·응답만 교환한다.

AI OWNS

결정과 계획

후보 비교, 그래프 탐색, 경로 비용, 대형 슬롯, 생성·검증, 재시도 예산, 복구 단계와 설명 기록을 소유한다.

GAME OWNS

사실과 실행 결과

문이 실제로 열렸는지, 전투가 시작됐는지, 애니메이션이 끝났는지, 캐릭터가 죽었는지와 명령 성공 여부를 소유한다.

ADAPTER OWNS

번역과 호환성

게임 객체를 안정 ID와 tag로 매핑하고 좌표·시간·비용을 고정 단위로 변환한다. 지원하는 aiApiRange를 manifest에 명시한다.

SAVE OWNS

재생에 필요한 버전

gameBuild, aiVersion, aiApiVersion, generatorVersion, configHash, seed와 활성 transition token을 저장해 로드 결과를 설명한다.

명령 계약코어는 상태를 쓰지 않고, 게임은 이유 없는 결정을 만들지 않는다

모든 명령은 사전조건 해시와 중복 실행 방지 키를 가진다. 게임이 명령을 거절하면 AI가 위치를 억지로 보정하지 않고 CommandResult를 받아 다음 결정 주기에서 재계획한다.

INDEPENDENT VERSIONING

문서, AI 코어, 어댑터와 게임 빌드는 같은 번호를 강요하지 않는다

현재 공개 문서는 v0.5.1이고 AI 구성요소는 v0.1.0이다. 문구 수정으로 게임을 다시 빌드하지 않으며, 게임 콘텐츠 패치 때문에 검증된 알고리즘 바이너리를 불필요하게 바꾸지 않는다.

DESIGN FREEZE · v0.1.0

1차 기획은 방향이 아니라 제작 기준선으로 동결한다

동결은 아이디어를 더 이상 내지 않는다는 뜻이 아니다. 핵심 판타지와 플레이 계약을 고정하고, 새로운 제안은 정해진 수용 게이트를 통과할 때만 다음 버전에 넣는다는 뜻이다.

플레이어가 개척단의 파티·장비·위험 정책을 관리하면, 원정대가 미지의 지역을 자동 탐사하고 위협을 제거해 정착촌을 성장시킨다. 직접 지휘하면 더 어려운 목표를 일찍 공략하지만, 접속하지 않아도 세계는 멈추지 않는다.

고정

핵심 플레이 계약

자동 진행은 기본값이다. 유저 관리는 효율과 조기 도전을 높이되 진행의 필수 입력이 되지 않는다. 실패는 성당 부활·복구 임무·재계획으로 다음 목표를 만든다.

조정 가능

수치와 콘텐츠 양

전투력 배율, 부활 시간, 지역 크기, 아이템 수, 던전 길이는 플레이테스트로 바꾼다. 수치 변경은 핵심 계약을 바꾸는 것으로 보지 않는다.

변경 절차

새 시스템은 다음 버전으로

핵심 루프·저장 구조·진행 상태를 바꾸는 제안은 목적, 대체안, 자동화 영향, 완료 지표를 기록하고 v0.1.x 또는 다음 기획 버전에서 검토한다.

버전 의미v0.1.0은 기획 동결 버전이며 게임 빌드 버전이 아니다

이 문서를 이후 구현과 콘텐츠 판단의 기준으로 사용한다. 구현 중 핵심 계약이 바뀌면 조용히 덮어쓰지 않고 변경 이유와 영향을 남겨 새 문서 버전으로 올린다.

FOUR-PHASE TIMELINE

넓히기 전에 한 바퀴를 닫고, 닫힌 고리에만 깊이를 붙인다

각 단계는 앞 단계의 플레이 가능한 결과를 보존한다. 다음 단계 기능 때문에 자동 원정이 다시 멈추거나 설명 불가능해지면 이전 게이트로 되돌아간다.

PHASE 01 플레이 가능한 버티컬 슬라이스 개척 야영지 → 횡구조 탐험 → 심층 던전 → 보스 → 귀환
PHASE 02 변주·액티브 연결 바이옴 문법 · 현상금 · 집중 작전 · 전술 교리
PHASE 03 장기 이력·계승 인물 이력 · 은퇴 교관 · 가보 · 대개척 헌장
PHASE 04 콘텐츠 확장 검증된 데이터 문법으로 지역·적·사건·빌드 확대
PHASE 01 · CORE PLAYABLE

한 지역을 처음부터 끝까지 실제로 완주한다

범위: 숲 바이옴 1개, 개척단 3인, 개척 야영지 1곳, 횡구조 탐험지 3곳, 2층 심층 던전 1개, 중간 보스와 최종 보스, 길드 게시판·예배당·대장간의 최소 기능.

핵심: 자동 길찾기와 전투, 위험도 도전·회피 정책, 장비 자동 판단, 전멸 시 본진 부활, 재도전 차단, 저장·오프라인 정산.

45–90분 한 바퀴입력 없이 완주한 가지 정착촌 변화
PHASE 02 · VARIETY & ACTIVE

직접 볼 때와 맡겨둘 때가 서로 다른 재미를 만든다

범위: 숲·황야·늪 3개 바이옴, 바이옴별 생성 문법, 퀘스트 던전, 연속 현상금, 지역 보스 집중 작전, 제한된 전술 명령, 발견한 대응을 자동 정책으로 저장하는 길드 교리.

핵심: 액티브 지휘는 낮은 전투력 조기 공략과 결과 선택권을 주지만, 임무를 보류해도 기본 자동 원정은 계속된다.

다른 화면다른 판단액티브 → 자동 학습
PHASE 03 · LONG-TERM LEGACY

원정의 기록이 캐릭터와 다음 개척지에 남는다

범위: 배경·재능·특징·부상·숙적 이력, 정착촌 안정화 역할, 영웅 은퇴와 교관 배치, 전투 이력이 새겨진 가보, 전술 전승, 첫 대개척 헌장.

핵심: 강한 숫자를 전부 가져가는 계승이 아니라 교관 1명, 가보 1개, 교리 1개를 골라 다음 캠페인의 전략을 바꾼다.

인물 애착월드 흔적수평 계승
PHASE 04 · CONTENT SCALE

새 시스템보다 검증된 조합의 폭을 늘린다

범위: 추가 바이옴, 직업 분기, 출신 배경, 보스 기믹, 사건 모듈, 던전 목표, 정착촌 특화, 대개척 헌장 규칙. 후반 다중 파티 레이드는 기반 성능이 확인된 뒤 별도 게이트로 검토한다.

핵심: 새 콘텐츠가 코어 코드를 고치지 않고 데이터와 리소스 조합으로 추가되어야 한다.

DEFINITION OF DONE

“구현됨”이 아니라 다음 단계로 넘어가도 되는지를 판정한다

LOCK기획 기준선 확정핵심 판타지 · 자동 계약 · 실패 복구 · 제외 항목에 미해결 충돌 0
GATE 01무인 완주와 안전한 복구지역 한 바퀴 · 저장 복원 · 오프라인 · 전멸 복귀가 중복 보상 없이 종료
GATE 02변주와 선택 차이 증명바이옴·목표·정책·액티브 명령이 실제 경로와 결과를 다르게 만듦
GATE 03두 번째 캠페인의 다른 전략계승 선택으로 시작 조합·목표 우선순위·공략 경로가 달라짐
GATE 04콘텐츠 생산 파이프라인새 지역과 사건을 코어 수정 없이 추가하고 기존 루프 회귀 0
단계완료 조건통과 전 만들지 않는 것
기획 동결핵심 용어·상태·콘텐츠 책임이 문서 간 충돌하지 않고, 새 제안 수용 기준과 제외 범위가 기록됨개별 콘텐츠 대량 제작
1차 버티컬 슬라이스8시간 무입력 진행에서 무기한 정지 0, 동일 저장 복원 결과 일치, 보상 중복 0, 생성 지도 10,000개가 성공 또는 명시적 폴백으로 종료추가 바이옴·직업·대형 스토리
2차 변주·액티브최근 10회 원정 중 고유 경험 서명 7개 이상, 30분 관전 중 5분 이상 무변화 구간 0, 집중 작전을 무시해도 자동 루프 정지 0장기 계승 트리·다중 파티
3차 장기 계승서로 다른 유산 선택으로 두 번째 캠페인의 파티·정책·지역 공략 순서가 달라지고, 이전 정착촌은 수동 관리 없이 효과를 제공무한 성장층·다지역 동시 관리
4차 콘텐츠 확장새 바이옴·보스·사건을 데이터 중심으로 추가하고 자동 탐색·저장·오프라인·보상 원장의 전체 회귀 검증을 통과새 코어 시스템의 상시 추가
게이트 원칙한 항목이라도 핵심 진행을 멈추게 하면 다음 단계로 가지 않는다

희귀 교착, 같은 보스 무한 재도전, 저장 후 다른 결과, 보상 복제는 콘텐츠 부족보다 먼저 해결한다. 자동 게임에서 안정성은 기술 부채가 아니라 플레이 품질이다.

NOT NOW

좋은 아이디어여도 지금의 핵심을 흐리면 보류한다

아래 항목은 영구 폐기가 아니라, 버티컬 슬라이스와 장기 순환이 검증되기 전에는 제작하지 않는 범위다.

보류 01

완전한 정착촌 시뮬레이션

건물 자유 배치, 주민별 직업·주거·식량, 유지비, 도로 건설은 별도 도시 게임을 만든다. 정착촌은 원정 결과가 보이고 기능이 열리는 경량 허브로 유지한다.

보류 02

림월드 수준의 인체·관계 시뮬레이션

신체 부위 전체, 욕구, 가계도, 수십 관계를 관리하지 않는다. 출신·재능·특징·주요 부상·활성 관계만 남기는 배틀 브라더스식 경량 구조를 사용한다.

보류 03

별도 액션 게임 수준의 수동 전투

조이스틱 이동과 스킬 연타보다 집중 대상, 진형, 궁극기 보존, 철수 같은 제한된 파티 지휘를 우선한다.

보류 04

여러 마을·여러 파티의 동시 수동 관리

과거 정착촌은 안정화 뒤 자동 운영한다. 다중 파티 레이드는 단일 파티 루프와 화면 가독성이 확인된 후 검토한다.

보류 05

무한층과 수치 인플레이션

같은 전투의 숫자만 높이는 무한 던전보다 바이옴, 목표, 사건, 위험 정책과 유산 선택의 조합을 먼저 늘린다.

제외 06

일일 숙제·기간 한정·BM 중심 구조

실시간 만료 퀘스트, 반복 수금, 로그인 보상, 패스, PvP·길드 의무는 1차 게임성 범위에서 제외한다. 콘텐츠는 플레이 행동으로 변화하고 사라지지 않는다.

범위 경고새 메뉴 하나는 새 상태·저장·설명·오프라인 규칙을 함께 만든다

기능의 화면 크기가 작다고 제작 부담도 작은 것은 아니다. 새 기능이 자동 원정, 저장, 복구, 정산 네 영역에 미치는 비용을 계산하지 못하면 보류한다.

FEATURE INTAKE GATE

새 기능은 여섯 질문을 통과할 때만 로드맵에 들어온다

GATE A핵심 판타지개척단의 탐험·관리·정착 중 하나를 강화하는가?
GATE B새로운 판단새 숫자가 아니라 경로·편성·위험 선택을 바꾸는가?
GATE C자동 기본값유저가 보지 않아도 기본 정책으로 종료되는가?
GATE D액티브 선택성직접 지휘는 효율과 결과를 바꾸되 필수가 아닌가?
GATE E흔적과 설명캐릭터·월드·정착촌에 결과가 남고 이유를 읽을 수 있는가?
GATE F유한 복구실패·저장·오프라인에서도 중복 없이 끝나는가?
판정조건처리
수용C 자동 기본값과 F 유한 복구를 반드시 통과하고, 전체 6개 중 5개 이상 충족현재 단계의 백로그에 목적·지표·완료 조건과 함께 등록
프로토타입재미 가치는 높지만 판단 변화나 액티브 효과가 아직 측정되지 않음분리된 실험에서 검증하고 본편 저장 구조에는 연결하지 않음
보류핵심과 어울리지만 새 화폐·새 메뉴·새 관리 주기가 과도함기존 시스템 조합으로 축소할 방법을 찾을 때까지 대기
거절확인 버튼, 수동 수금, 실시간 만료, 무한 재도전처럼 진행을 멈추거나 FOMO를 만듦로드맵에 넣지 않음

새 기능은 다음 원정의 선택을 바꾸고, 화면이나 월드에 흔적을 남기며, 유저가 없어도 끝나야 한다.

01 · LOCAL SOURCE

원본 검토

  1. 버전·날짜 일치페이지 표기, 변경 요약, 백업 이름이 v0.3.1 · 2026-07-26으로 일치한다.
  2. 범위 동결 확인핵심 계약, 단계, 보류 항목, 새 기능 수용 기준이 빠짐없이 기록되었다.
  3. 링크·이미지 확인모든 내부 링크와 이미지 경로가 존재하고 새 창을 불필요하게 열지 않는다.
  4. 화면 검토PC 기준에서 타임라인·표·카드가 겹치거나 잘리지 않는다.
02 · GIT HISTORY

버전 기록

  1. 변경 범위 확인이번 버전에 포함할 파일만 변경되었고 임시 파일·대용량 원본은 제외했다.
  2. 명확한 커밋1차 기획 동결과 제작 로드맵이라는 목적이 커밋 메시지에서 드러난다.
  3. 비공개 기준 태그검증할 게임 원본 커밋에 v0.3.1 태그를 부여하고 원격 저장소에 반영한다.
  4. 작업 상태 정리배포 전 미기록 변경이 없는지 확인한다.
03 · GITHUB PAGES

공개본 확인

  1. 배포 완료공개 페이지가 v0.3.1 내용을 제공하고 이전 캐시가 남지 않는다.
  2. 주요 경로 점검표지 → 로드맵 → 이전·처음 이동과 페이지 내 목차가 현재 창에서 작동한다.
  3. 시각 자료 점검이미지 로딩, 확대 보기, 카드·표·게이트의 가독성을 실제 공개 주소에서 확인한다.
  4. 오류 시 되돌림공개본을 직접 고치지 않고 로컬 수정 → 새 커밋 → 재배포 순서를 지킨다.
04 · GOOGLE DRIVE

버전 백업

  1. 공개 검증 후 압축GitHub Pages 확인이 끝난 동일 커밋의 파일만 보관한다.
  2. 파일명 고정프로젝트명, 버전, 날짜를 파일명에 포함해 검색과 정렬이 가능하게 한다.
  3. 압축 무결성 확인압축을 다시 열어 HTML·자산 누락이 없는지 확인하고 체크섬을 기록한다.
  4. 덮어쓰기 금지수정본은 기존 v0.1.0을 바꾸지 않고 새 패치 버전으로 추가한다.
